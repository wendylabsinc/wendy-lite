# Linux router mesh fixtures

These are the `bundle` and `manifest` control messages a Linux Wendy Net router
sends to a Lite leaf, byte for byte. They were generated by the router's own
code: `localmesh.SignManifest` and `json.Marshal(ControlMessage{...})` from
WendyOS PR #2466 (`jo/mesh-cli`, a65ea8a62), which signs ML-DSA device keys.
The keys are disposable and were discarded. The certificates are test data, not
Wendy production trust roots.

- `roots.pem`: an ML-DSA-87 root. The bundles carry the rest of the production
  enrollment shape: an ML-DSA-87 customer CA, then ML-DSA-65 tenant and identity
  CAs, then the device leaf. As with the router's TLS chain, the root is omitted.
- `mldsa-router-*`: an ML-DSA-65 router. Its manifest signs the raw v3 input,
  `wendy-local-mesh/manifest/3\0 || uint32_be(105) || principal || body`, with
  pure ML-DSA-65 and an empty context (`crypto.Hash(0)`).
- `mldsa-router-manifest-{hashed,context,no-principal,other-key}.json`: the
  same manifest with an ML-DSA-65 signature over SHA-256 of the input, with a
  non-empty context, over the input without the principal, or by another key.
  The router's verifier rejects each one.
- `ecdsa-router-*`: a P-256 router through the same signer: ECDSA over SHA-256.
- `other-root.pem`: a root with the same name and algorithm but another key.
- `vector.txt`: tenant, ML-DSA router, P-256 router, signing time and leaf
  expiry in Unix seconds. The test verifies at that signing time.

Both manifests include the signed `agent` metadata that the WendyOS agent adds
to its own announcements.

## Regenerate

`router_vectors_test.go` is compiled into a WendyOS checkout's `localmesh`
package through a Go overlay; it is not part of either repository's build.
With Go 1.27 or newer, from the root of a WendyOS checkout containing PR #2466:

```sh
fixtures=/path/to/wendy-lite/components/wendy_mesh/tests/mldsa-router-fixtures
printf '{"Replace":{"%s/go/internal/agent/localmesh/zz_lite_router_vectors_test.go":"%s/router_vectors_test.go"}}' \
  "$PWD" "$fixtures" > /tmp/lite-vectors-overlay.json
WENDY_LITE_VECTOR_DIR="$fixtures" go test -tags wendy_lite_vectors \
  -overlay /tmp/lite-vectors-overlay.json -run '^TestLiteRouterVectors$' \
  ./go/internal/agent/localmesh
```

Regeneration uses fresh keys, so certificate and signature bytes change. The
UUIDs and the signing time stay fixed.
