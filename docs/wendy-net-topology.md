# Reading Wendy Net topology

The read-only WendyCom `net_topology` command24 / response9 reports this device's authenticated links, selected exact routes and verified announcement projections. It uses the existing full-role physical or authenticated Cloud management connection. It does not start mesh participation, change saved policy or return certificates, signatures, keys or signed bodies. Device-role SensorLink connections retain their existing SensorLink-only allowlist.

Each binary-protobuf reply contains at most one public metadata record and an opaque next cursor. Start with cursor/generation zero, then echo the returned generation and next cursor until it is zero. A changed structural view returns BUSY; discard collected rows and retry at most once. Ordinary routing counters/timer work do not invalidate the view. Serial clients bound collection to1024 rows,512KiB and60s; they never claim a coherent full snapshot assembled across generations.

The application task submits one charged mailbox to the main actor, with a two-second wait. It never reads mutable router state or lends a caller buffer after timeout; the actor rejects waiting on itself. Independent references cover pre-pickup cancellation, an actor that outlives its timed-out caller and queued OFF. On the64-bit host the fixed page is320B and mailbox352B; the selected device fixture encodes114B, operator fixture203B and maximum1024-byte principal fixture1152B. No fixed principal array, per-origin snapshot array or persistent snapshot cache is added. OFF obtains existing public identity/status without opening the runtime ledger, creating an actor/mailbox or leaving mesh heap. The actual production caller/actor functions and ledger drainage are compiled in the normal host fixture.

`owner_role` distinguishes device(1) and operator(2); zero retains the original device encoding. `device` is only an enrolled device UUID. An operator instead has exact case-sensitive `owner_principal` and sixteen-byte `owner_instance`, its routing installation UUID. Its verified address is in the5680 allocation. These are public metadata, not additional authority. The generic actor extension hook defaults to no operator state; the following operator-authority delivery projects its verified entries and routes. Endpoint gateway/C6 allocates no operator registry. Current next-hop device metadata stays a real device neighbor.

Operator principal strings use a nanopb callback, not a fixed1025-byte page member. Scans/hash computation borrow metadata only within the actor turn. Only the selected operator row obtains an immutable copy, capped at1024 bytes, on the charged runtime ledger. Both response sizing and encoding read the same copy. Successful encoding, encoder/output-budget failure, timeout and OFF each release it exactly once. A transferred row keeps the closed ledger undrained until its encoder releases it; runtime reopen cannot race that loan. The production dispatcher fixture includes a normal maximum-length subject that exceeds a provider's output budget.

The narrow `wnrs_topology_operator_row` extension receives a borrowed `wnt_record_view`. Category2 receives the existing route address/router/sequence and fills only its verified operator owner; category3 returns the indexed live operator announcement after device/endpoint rows. It returns1 for found,0 absent,-1 unavailable and allocates nothing. The caller hashes semantic role/principal/instance bytes and clones only the selected export. No pointer, padding or timer counter contributes to generation.

Endpoint gateway profiles intentionally retain a compact partial directory. Their replies set `partial`; clients preserve that limitation and do not fabricate remote route tables or full signed origin tuples. A stopped/unready runtime exports no links or routes. Live device proof expiry is bounded by both certificate and signed manifest validity. Existing settings receipt/output-drain barriers, immutable crypto context loans, actor teardown and task/heap ledger drainage remain unchanged.

CLI and UI adapters normalize UUID/address bytes into canonical UUID/IPv6 text before any JSON envelope; raw generated bytes would become base64 and must not be exposed. Preserve all uint64 link/router/revision values as decimal strings. The normal C→Go→C binary fixture includes an operator installation distinct from the Lite reporter's device identity, canonical5680 address, and maximum uint64 IDs. The paired WendyOS adapter must exercise the same fixture when adding the typed fields. No WendyCom Swift binding exists to regenerate; the affected existing bindings are C/nanopb and console Go here, and WendyOS Go in the paired adapter delivery.
